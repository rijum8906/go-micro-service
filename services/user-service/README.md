# User Service

The User Service is the identity and session management service for the Relay
backend. It exposes gRPC endpoints for authentication, user profile operations,
and session lifecycle management, backed by PostgreSQL for persistence and Redis
for token and cache workloads.

## Responsibilities

This service owns:

- user registration and login
- access token and scoped token issuance
- session creation, refresh, and revocation
- user and profile data access
- auth-related persistence and validation flows

## Stack

- Go `1.26`
- gRPC
- PostgreSQL
- Redis
- `sqlc` for typed query generation
- Atlas for schema and migration management

## Repository Context

This service is part of a larger monorepo and depends on shared local modules:

- `../../packages/core`
- `../../packages/pb`

Run commands from this service directory unless noted otherwise. Docker builds
use the monorepo root as the build context.

## Development

For active development, schema changes, and migration management, use the Atlas-based workflow:

### Workflow

1. **Initialize Database**: Create the main and development databases if they don't exist.

   ```bash
   rcli db init
   rcli db init -t # to create the test database
   ```

2. **Apply Migrations**: Sync your database with the current migration set.

   ```bash
   rcli db migrate apply
   rcli db migrate apply -t # to apply migrations to the test database
   ```

3. **Generate New Migration**: After changing `db/schema.sql`, generate a new migration file.

   ```bash
   rcli db migrate new --name your_change_name
   ```

4. **Other Commands**:
   - `rcli db migrate status`: Check migration status.
   - `rcli db migrate rollback`: Roll back the last migration.
   - `rcli db migrate reset`: Wipe the database and re-apply all migrations.

## Notes For Contributors

If It's your first time then I recommend you to read first the core packages README.md
[Core README.md](../../packages/core/README.md)

### App

- If you are adding a new env variable in app/config/env.go , please add it to the `.env.example` file as well. and add a comment explaining what the variable is for only if the variable is not self-explanatory.
- Do not change anything in app/*.go files. These are related to the main application logic and should not be modified. If you actually need to change something in these files, discuss with the maintainers first.
- I used singleton pattern for the main application.
- I would recommend to have a look at app/app.go , app/implementation.go and app/registry/registry.go
- app/constants/ contains constants used throughout the application and among different services.

### Database

- Do not update the db/schema.sql file without discussion.
- After updating the db/schema.sql file, run `rcli db migrate new --name <your_change_name>` to generate a new migration. But if this is not yet released in production then just delete the migration files and then run `rcli db migrate new --name initial_schema` to generate a new migration from scratch.
- Before updating or create new sqlc queries, please have a look at the existing queries and follow the same pattern.

### Services

- Each service should have its own package under `app/services/`.
- Before creating a new service, please have a look at the existing services and follow the same pattern. internal/services/*/interfaces.go
- With each method in a service add tests.
- Use notations like `TODO:`, `FIXME:`, `SECURITY:`, `IMPORTANT:`, `NOTE:`, `BUG:` and more
